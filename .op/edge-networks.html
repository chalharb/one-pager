Networking · Two-page summary

How edge networks work

An edge network answers requests from servers placed near users instead of from one distant origin. Because every round trip is limited by the speed of light, moving work closer is the most reliable way to make a site faster, cheaper to run, and harder to knock over.

What an edge network is

An edge network is a fleet of servers spread across many points of presence (PoPs): data centres placed close to users and well connected to their internet providers. The origin is the server that holds the real content. Instead of crossing continents to reach it, each user talks to a nearby PoP, which answers from its cache, runs code, or fetches from the origin on the user's behalf. Content delivery networks (CDNs) are the best-known kind.

How a request finds the nearest edge

  • DNS steering. The provider's DNS answers each lookup with the address of a nearby PoP.
  • Anycast. Every PoP announces the same IP address over BGP, and internet routing delivers each user to the nearest one.

The path of a request

Why distance matters

Light in fibre travels at about 200,000 km per second, two-thirds of its speed in a vacuum. That sets a floor no software can beat: every 1,000 km between user and server adds about 10 ms to each round trip, before detours and queueing.

What one round trip costs

A new HTTPS connection over TCP and TLS 1.3 waits three round trips for its first byte:

  1. TCP handshake
  2. TLS 1.3 handshake
  3. Request and response

HTTP/3 runs on QUIC, which merges the first two. Each round trip pays the distance again.

What the edge keeps, and for how long

The origin's response headers decide what is cached. The edge files each response under a cache key: the URL, plus any request headers named in Vary.

  • max-age sets how long a copy stays fresh; s-maxage overrides it for shared caches like the edge.
  • Revalidation checks a stale copy with ETag; a 304 reply renews it without resending the body.
  • stale-while-revalidate serves the old copy while fetching a new one.
  • private and no-store keep personal data out.

Why hit ratio matters

Every miss goes to the origin, so small gains in hit ratio cut origin load sharply. A shield tier funnels misses from many PoPs through one cache, so the origin sees each object once.

More than a cache

  • TLS termination. Handshakes end at the nearby PoP, which keeps warm connections to the origin.
  • Attack absorption. A flood is spread across every PoP instead of one origin.
  • Edge functions. Small programs run in the PoP: redirects, A/B tests, auth checks.
  • Request collapsing. Many requests for one uncached object become one origin fetch.
